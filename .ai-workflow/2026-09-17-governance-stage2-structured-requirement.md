# 结构化开发需求：治理门禁 Stage 2 收口

> 日期：2026-09-17 ｜ 负责人：sandysu737-source ｜ 执行人：Codex

## 1. 业务目标
将 AI 工程化治理从“可被本地环境变量与伪造工具绕过”升级为 fail-closed 门禁，并用对抗测试锁定行为。

## 2. 输入参数定义
| 名称 | 类型 | 必填 | 默认 | 校验规则 |
|---|---|---|---|---|
| `AI_ENG_KIT` | 环境变量 | 否 | 无 | 本地不再允许覆盖治理脚本路径 |
| `AI_REVIEW_CI` | 环境变量 | 否 | `0` | 仅 `GITHUB_ACTIONS=true` 时可作为 CI 模式 |
| `AI_REVIEW_CONFIRMED` | 环境变量 | 否 | `0` | 仅负责人显式授权单人治理通道时为 `1` |
| `RADON_BIN` / `RUFF_BIN` / `BANDIT_BIN` / `PYTEST_BIN` | 路径 | 否 | PATH | 必须存在、可执行且不是 `true` / `false` |
| 暂存文件列表 | `string[]` | 是 | git staged | 风险定级和质量门禁只接收暂存文件 |

## 3. 输出数据结构
| 输出 | 位置 | 语义 |
|---|---|---|
| 门禁报告 | `.ai-governance/reports/` | 每次运行的风险等级、通过项、失败项与结论 |
| 对抗测试汇总 | stdout | `PASS=6 FAIL=0 SKIP=0` 或失败 |
| 审计留痕 | CI log / `classify.txt` | 远端可复查的文件清单与定级结果 |

## 4. 依赖资源
- Bash 3.2 兼容运行时。
- `git`、`python3`、`ruff`、`pytest`、`radon`、`bandit`。
- 无数据库、网络服务或模型权重依赖。

## 5. 业务流程步骤
1. `ai-guard` 读取 git 暂存清单，禁止把工作区未暂存文件混入定级。
2. 固化治理脚本路径，忽略伪造 `AI_ENG_KIT`。
3. 校验工具二进制完整性，伪造工具直接失败。
4. `quality-gate` 执行静态扫描、SQL/会话风险检测、`nosec` 闭环、覆盖率与复杂度检查。
5. `review-token` 绑定分支、提交、暂存 hash 和 reviewer，防止签发后偷换内容。
6. CI 运行 `test-anti-evasion.sh` 与 hook 完整性检查。

## 6. 边界条件
- [x] `AI_ENG_KIT` 指向伪造目录时必须被忽略。
- [x] 工具指向 `/bin/true` / `/bin/false` 时必须失败。
- [x] 暂存文件为空时不得误扫工作区。
- [x] L2 本地不得通过伪造 `AI_REVIEW_CI=1` 放行。
- [x] `nosec` 必须绑定工单、路径、登记人和原因。
- [x] token 签发后暂存内容被偷换必须失效。

## 7. 异常场景
1. 治理 kit 缺失：返回非零，禁止降级为警告。
2. 工具不可执行或伪造：返回非零。
3. token 校验失败或格式不匹配：返回非零。
4. 对抗样例未被拦截：返回非零并阻断 CI。
5. 裸 `nosec` 或未登记豁免：返回非零。

## 8. 性能约束
- 对抗套件本地执行不超过 10 秒。
- 质量门禁只解析暂存文件，避免全仓库重复扫描。

## 9. 安全约束
- 不新增网络出口、数据库连接或凭据存储。
- 不打印 token 原文。
- 单人治理仅允许负责人显式确认，且 CI 仍保留 approved-review 服务端防线。

## 10. 必须覆盖测试用例
1. 正向：合法 L1/L2 流程可执行，合法 token 可通过。
2. 边界：空暂存、单人确认、真实 CI 环境指纹。
3. 异常：假 kit、假工具、假 CI、偷换暂存、危险 SQL/Session/空 catch、裸 `nosec`。
