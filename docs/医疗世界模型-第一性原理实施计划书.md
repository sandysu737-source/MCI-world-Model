## 第一层推导：世界模型的本质定义

### 什么是世界模型？

世界模型（World Model）的本质是一个**内化的环境模拟器**，让智能体能够在脑海中"预演"行动的后果，而不必在真实世界中试错（真实世界试错代价太高或不可逆）。

学术定义（Ha & Schmidhuber 2018; LeCun 2022 JEPA）：

```
世界模型 = 状态编码器 E + 转移预测器 T + (可选)奖励预测器 R

E: observation → state          （感知：把观测压缩为内部状态）
T: (state, action) → state'     （预测：给定动作，预测下一状态）
R: state → reward               （评估：状态的好坏）

智能体用 E+T+R 在脑内做规划：
   给定当前状态 s 和目标 g，
   搜索动作序列 a₁,a₂,...,aₙ 使得 T 链式预测的结果接近 g
```

### 世界模型的五个第一性要素

| 要素 | 本质问题 | 学术术语 |
|------|---------|---------|
| **状态空间 S** | "患者现在怎么样？" | State Representation |
| **动作空间 A** | "我能做什么？" | Action Space |
| **转移模型 T** | "如果我做 X，会发生什么？" | Dynamics / Transition Model |
| **评估函数 R** | "结果是好是坏？" | Reward / Objective |
| **规划器 π** | "给定目标，最优行动序列是什么？" | Planning / Policy |

**关键洞察：世界模型不是"因果推理引擎"。因果推理只是转移模型 T 的一种实现方式。世界模型是一个完整的感知-预测-行动闭环。**

## 第二层推导：医疗智能体世界模型的特殊性

### 医疗场景对五个要素的约束

通用世界模型（游戏/机器人）与医疗世界模型的根本差异：

| 要素 | 通用世界模型 | 医疗世界模型的特殊约束 |
|------|------------|---------------------|
| 状态 S | 连续向量（像素/关节角） | **异构时序**：生命体征(连续) + 检验值(离散) + 用药(事件) + 诊断(类别) |
| 动作 A | 连续控制（力矩/方向） | **离散+连续混合**：药物选择(离散) + 剂量(连续) + 操作(事件) |
| 转移 T | 物理方程/学习 | **多尺度**：秒级(心电图) + 分钟级(血压) + 小时级(检验) + 天级(预后) |
| 评估 R | 分数/胜负 | **多目标+约束**：死亡率 + 并发症 + 不确定性 + 安全约束(不可违反) |
| 规划 π | MCTS/RL | **可解释+可审计**：每步推理必须有医学依据，不能是黑箱 |

### 医疗世界模型的独特要求（区别于所有其他领域）

1. **安全关键性**：错误预测可能导致患者死亡 → 必须有不确定性量化 + 拒绝推断机制
2. **反事实推理**："如果当时没给这个药，患者会怎样？" → Pearl L3 是刚需，不是可选
3. **多源异构**：波形(高频) + 检验(低频) + 文本(病历) + 知识(指南) → 必须融合
4. **可解释性法规**：FDA/NMPA 要求 AI 医疗器械的决策可追溯 → 审计链是合规要求

## 第三层推导：项目现状的第一性审计

### 用五个要素审计当前项目

| 要素 | 应有（医疗世界模型） | 现有（代码审计结果） | Gap |
|------|-------------------|-------------------|-----|
| **状态 S** | PatientState（异构临床时序） | PendulumState / CartState / DoublePendulumState（物理玩具） | 🔴 无医疗状态空间 |
| **动作 A** | MedicalAction（药物+剂量+操作） | PendulumAction / CartAction（物理玩具） | 🔴 无医疗动作空间 |
| **转移 T** | 临床动态学预测器 | PendulumPhysicsPredictor（单摆物理方程） | 🔴 无医疗转移模型 |
| **评估 R** | 临床目标函数（死亡率/并发症） | MCTS reward = 1 - distance/initial_dist（欧氏距离） | 🔴 无医疗评估函数 |
| **规划 π** | 治疗方案搜索 | MCTSPlanner（在物理玩具状态上搜索） | 🔴 无医疗规划 |

### 根本诊断

**项目的"世界模型"目前只在物理玩具域（单摆/小车/双摆）上成立。**

医疗部分（ClinicalTriRouter + MedicalCausalSDK + CausalDAG）是一套**并行的因果推理工具**，但它不是世界模型——它没有状态空间、动作空间、转移模型、评估函数、规划器的闭环结构。

这就是"模块断裂"问题的第一性本质：**不是三个模块没接起来，而是医疗部分从未被建模为世界模型。它是一组因果推理工具，不是一个 world model。**

### 与 su-memory-sdk 的边界（严守）

```
┌─────────────────────────────────────────┐
│        su-memory-sdk（记忆引擎）          │
│  短期记忆 / 长期记忆 / 向量检索 / 持久化   │
│  ← 经验回放、案例库、跨会话状态归属此处    │
└──────────────┬──────────────────────────┘
               │ adapters/su_memory_bridge.py（已有，不扩展）
               ▼
┌─────────────────────────────────────────┐
│      MCI World Model（世界模型引擎）      │
│  本次计划的范围 ↓                         │
│                                         │
│  状态编码 E + 转移预测 T + 评估 R + 规划 π │
│  （无状态计算，不持久化，不检索记忆）       │
└─────────────────────────────────────────┘
```

**原则**：世界模型每次调用是独立的无状态计算。记忆/经验/案例库归 su-memory。如需跨调用状态，走桥接适配器，不在世界模型核心实现。

## 第四层推导：从本质出发的架构重建

### 目标架构：医疗世界模型闭环

```
                    ┌──────────────────────────────────────────────────┐
                    │              医疗世界模型闭环                       │
                    │                                                  │
  临床数据 ───→ E ──→ PatientState ──→ T(s,a) ──→ PatientState' ──→ R ──→ 临床目标值
  (FHIR/波形)   感知    (异构时序)     转移预测      (预测未来)      评估    (预后评分)
                    │                                                  │
                    │              ↑规划器 π                            │
                    │              搜索最优 a* 使得 R(s')最大化           │
                    │              （受安全约束）                        │
                    └──────────────────────────────────────────────────┘
```

### 四层重建路线（按依赖顺序）

#### 第一层：状态空间（地基，一切的前提）

**问题**：没有 PatientState，转移模型 T 无从定义。

```python
class PatientState(WorldState):
    """患者临床状态 — 异构时序世界状态。"""
    
    # 连续体征时序 (T, V)：HR/SBP/DBP/SpO2/RR/Temp/GCS
    vital_signs: np.ndarray        
    
    # 离散检验值（最新）：血钾/肌酐/白细胞/血红蛋白/血小板
    lab_values: dict[str, float]    
    
    # 当前用药列表：[(药物名, 剂量, 单位, 给药途径)]
    medications: list[Medication]    
    
    # 诊断标签（ICD-10）
    diagnoses: list[str]    
    
    # 时间戳（临床时间线锚点）
    timestamp: float
```

#### 第二层：动作空间（干预手段）

**问题**：没有 MedicalAction，规划器无法搜索治疗选项。

```python
class MedicalAction(Action):
    """临床干预动作。"""
    
    action_type: ActionType       # DRUG / PROCEDURE / VITAL_ADJUST
    target: str                   # 作用对象（药物名/操作名）
    magnitude: float              # 剂量/强度（连续）
    unit: str                     # 单位
    route: str = ""               # 给药途径（IV/PO/IM）
```

#### 第三层：转移模型（世界模型的核心）

**问题**：现有转移模型是物理方程，需要医疗动态学预测器。

三条并行路径（对应三元路由）：

| 路径 | 转移模型 | 回答的问题 |
|------|---------|----------|
| 生理动力学 | `ClinicalDynamicsPredictor` | "给药后体征如何变化？" |
| 因果效应 | `CausalEffectPredictor`（已有 intervene） | "干预的因果效应多大？" |
| 知识推理 | `KnowledgeBasedPredictor`（已有 KB） | "指南怎么说？" |

#### 第四层：评估+规划（闭环顶端）

**问题**：没有临床目标函数，规划器不知道什么是"好结果"。

```python
class ClinicalObjective:
    """临床目标函数。"""
    
    def reward(self, state: PatientState) -> float:
        """评估状态好坏。
        
        组合多个临床指标：
        - 体征稳定度（越接近正常范围越高）
        - 器官功能（SOFA评分越低越好）
        - 安全约束违反惩罚（越界值重罚）
        """
    
    def is_safe(self, state: PatientState) -> bool:
        """安全约束检查（硬约束，不可违反）。"""
```

## 第五层推导：分阶段实施计划

### 总原则

**从地基往上建，不跳层。** 状态空间没建好，转移模型就是空中楼阁；转移模型没验证，规划器就是无本之木。

### Phase 0：状态+动作空间（第 1-3 天，地基）

| 天 | 任务 | 文件 | 验证 |
|----|------|------|------|
| D1 | `PatientState` + `MedicalAction` 数据结构 | `sdk/_clinical_world_state.py` | 单元测试：构造/序列化/距离计算 |
| D2 | `ClinicalStateEncoder`：FHIR/波形 → PatientState | `sdk/_clinical_state_encoder.py` | 7维体征正确编码 |
| D3 | `PatientState.distance()` + 安全约束检查 | 同 D1 | SOFA 评分 + 生理范围校验 |

**为什么是第一步**：转移模型 T(s,a)→s' 依赖 S 和 A 的定义。没有 PatientState 和 MedicalAction，T 无从写起。

### Phase 1：医疗转移模型（第 4-7 天，核心）

| 天 | 任务 | 文件 | 验证 |
|----|------|------|------|
| D4 | `ClinicalDynamicsPredictor`：体征时序前向预测 | `sdk/_clinical_dynamics.py` | 12步历史→3步预测，MAE 达标 |
| D5 | 接入 JEPA：PatientState → 潜空间 → 预测 → 解码 | 同 D4 | JEPA 在患者状态上跑通 |
| D6 | 在 MIMIC 波形数据上验证预测精度 | `scripts/jepa_mimic_validation.py` | 方向准确率 > 70% |
| D7 | `CausalEffectPredictor` 适配：MedicalAction → 因果效应 | 同 D4 | do(多巴胺)→心率 效应正确 |

**为什么在状态之后**：T 的输入是 PatientState + MedicalAction，输出是 PatientState'。Phase 0 不完成，Phase 1 无法开始。

### Phase 2：评估+规划闭环（第 8-11 天，闭环）

| 天 | 任务 | 文件 | 验证 |
|----|------|------|------|
| D8 | `ClinicalObjective`：临床目标函数 + 安全约束 | `sdk/_clinical_objective.py` | reward 和 is_safe 正确 |
| D9 | `ClinicalMCTSPlanner`：在医疗状态上搜索治疗方案 | `sdk/_clinical_planner.py` | 能搜索"给药→预测→评估"链 |
| D10 | 端到端闭环：状态→规划→执行→审计 | `sdk/_clinical_decision_engine.py` | 3种场景跑通 |
| D11 | 集成测试 + FHIR 输入适配 | `adapters/fhir/` | FHIR→State→Plan→Decision |

**为什么最后做**：规划器 π 需要 T（转移）和 R（评估）都就绪才能工作。评估函数 R 需要知道 PatientState 结构才能定义。

### Phase 3：验证与合规（第 12-14 天，可信度）

| 天 | 任务 | 交付物 |
|----|------|--------|
| D12 | 不确定性量化：每个预测附带置信区间 | 贝叶斯 bootstrap 集成 |
| D13 | 端到端 ICU demo + 审计链验证 | 演示脚本 + 审计报告 |
| D14 | 回归测试 + 文档 + ruff/mypy | 全量 pytest 全绿 |

## su-memory-sdk 边界（再次强调）

本计划的 14 天工作**全部在世界模型引擎内部**：

- ✅ 状态编码（FHIR→PatientState）：世界模型的感知功能
- ✅ 转移预测（PatientState+Action→State'）：世界模型的核心
- ✅ 评估规划（Objective+MCTS）：世界模型的决策功能
- ❌ 经验存储/检索/持久化：su-memory-sdk 职责
- ❌ 案例库/跨会话状态：su-memory-sdk 职责
- ❌ 向量索引：su-memory-sdk 职责

`ClinicalDecisionEngine` 是**无状态编排层**，每次调用独立计算，不持有跨调用状态。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| PatientState 设计过度复杂 | 先支持 7 维核心体征，检验/用药后续迭代 |
| MIMIC 数据不可访问 | 降级用 Sachs 半合成数据；如实报告 |
| JEPA 在真实波形上效果差 | 如实呈现，作为 Phase 3+ 改进输入 |
| 临床目标函数主观性强 | 用 SOFA 评分等客观量表，不用自造指标 |
